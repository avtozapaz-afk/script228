# AVTOZAP — сквозной прогон конвейера на реальных fresh-300

Харнесс прогоняет **сырой текст покупателя** через весь конвейер и выдаёт по
каждому запрошенному предмету реальный `external_code` словаря либо честный
`UNKNOWN`.

```
RAW REQUEST
  → Layer 0 (семантическая сегментация, LLM PASS A)
  → OEM / part-number резолвер
  → слой фото-доказательств
  → Retriever V2
  → Arbiter V3 (ЗАМОРОЖЕН)
  → жёсткий валидатор
  → итоговый external_code / UNKNOWN
```

Продуктовая модель для всех LLM-стадий — **`gpt-4.1-mini`**.
Только Python 3.9+ (проверено на 3.11). Ни `.cmd`, ни `.bat`, ни PowerShell
не требуется.

---

## Одна команда

```bash
pip install -r requirements.txt          # 1. один раз
export OPENAI_API_KEY="sk-..."           # 2. или пропустите — спросит скрытым вводом
python run_test.py                       # 3. все 300 свежих заявок
```

Перед полным прогоном — **дымовой тест на 5 заявках** (единственная команда,
которую осталось выполнить с живым ключом):

```bash
python run_test.py --max-requests 5
```

На выходе в `out/` (папка создаётся сама):

| файл | что внутри |
|---|---|
| `results.jsonl` | по строке на атомарный предмет, пишется сразу — основа возобновления |
| `results.csv` | та же таблица плоско, 43 колонки, UTF-8 BOM для Excel |
| `summary.json` | сводка машинно |
| `summary.md` | сводка для чтения |
| `failure_analysis.md` | каждый провал отнесён к первому ответственному слою |
| `errors.log` | трассировки сбойных запросов |

Плюс `LIVE_RUN_ANALYSIS.md` в корне — разбор прогона от 31.08 с цифрами.

Прогон **возобновляемый**: результат каждого предмета сбрасывается на диск
(`flush` + `fsync`) сразу, повторный запуск той же команды пропускает уже
посчитанное. Прервать можно в любой момент, включая `Ctrl+C`.

## Что в поставке авторитетно, а что нет

Разбор присланных материалов дал три расхождения, которые важно знать, потому
что они меняют, какой файл считать источником истины.

| файл | что в нём на самом деле | используется |
|---|---|---|
| `AVTOZAP_slovar_v8_FINAL.xlsx` (поставка v8 + согласованная правка MU-038) | **571 деталь**, 4666 терминов, 5 правил `AMBIGUOUS_RULES` | **да — источник истины**, лежит как `data/AVTOZAP_slovar_FINAL_571.xlsx` |
| `02_DATA/SLOVAR_FINAL_541_REFERENCE.txt` | вопреки имени — **435 деталей**, без флагов side/position | нет |
| `02_DATA/parts_synonyms_cleaned_v2.xlsx` | **537 деталей** — та самая «старая» версия | нет |
| `01_PIPELINE/ARBITER_V3_PROMPT.txt` | настоящий V3 | **да, байт в байт** |
| `04_prompt/AVTOZAP_SEGMENTER_V1.txt` | промпт Layer 0 | **да, байт в байт** |
| `03_TESTS/AVTOZAP_FRESH_300_V4_DEVSET.json` | 300 заявок + прежние `item_raw` и кандидаты | **только `original_text`** |
| `03_TESTS/AVTOZAP_otlozhennyy_nabor_300.json` | отдельный отложенный набор | лежит в `data/reference/`, в прогон не входит |
| `04_REFERENCE_RESULTS/*.csv` | прежнее поведение арбитра | справка для диагностики, не истина |

Проверка «541 деталь» зафиксирована тестом `test_exactly_541_parts`, включая
`AK-004`, `AK-006`, `YA-027` и `MU-011` — именно их не было в версии на 537.

### Чего в поставке нет

1. **Размеченной истины.** `old_external_code` — код прежней боевой системы, и
   по правилам поставки эталоном он не является. Поэтому сквозная точность не
   считается: в `summary.md` раздел «Точность» честно сообщает, что поля
   `expected_external_code` во входе нет.
2. **Каталога OEM-номеров.** Номера извлекаются и классифицируются, но
   сопоставить их не с чем — статус `UNRESOLVED`. Ветки `MATCH`/`CONFLICT`
   написаны и покрыты тестами, включатся сами, как только появится
   `data/oem_catalog.json` формата `{"1K0615301AA": {"external_code": "EY-002"}}`.
3. **Фотографий.** Слой фото возвращает `NO_IMAGE`; визуальные свидетельства не
   выдумываются.

## Вход

Реальные 300 свежих заявок уже собраны в `data/requests_300.jsonl` — только
сырой текст:

```json
{"rfq_id": "fresh-001", "original_text": "W210 e230 termostat", "source_rfq_id": "a98d5392-…"}
```

Пересобрать из devset:

```bash
python scripts/build_fresh300_input.py
```

`item_raw` и `candidates` из devset на вход **не подаются**: это результат
работы прежних Layer 0 и Retriever V2, и кормить конвейер его же подсказками
значило бы измерять не то. Тест `test_the_real_fresh_300_input_is_readable`
следит, чтобы они не просочились.

Необязательные поля строки: `expected_external_code` (включает точность и
полный разбор по слоям), `image_path` / `image_url`.

## Слои

### Layer 0 — семантическая сегментация

Основной путь — **LLM PASS A** по промпту проекта `prompts/segmenter_v1.txt`
(тоже под контрольной суммой). Модель только делит сообщение на запрошенные
предметы и сохраняет формулировку покупателя; она не выбирает код и не
придумывает канонические названия — за этим следит разбор ответа.

Когда сети нет (`--mock`, `--dry-run`) или вызов не удался, работает
**детерминированный запасной сегментатор**. Сообщение обязано быть разобрано
всегда, иначе один сбой API стоил бы заявки; в колонке `layer0_source` видно,
кто именно сегментировал.

Запасной сегментатор дробит по разделителям и союзам, но держит одну и ту же
деталь в разных положениях одним предметом:

| вход | результат |
|---|---|
| `Naklatka və tormuz disk` | 2 предмета |
| `ön və arxa bufer` | 1 предмет, `position = on,arxa` |
| `sol və sağ güzgü` | 1 предмет, `side = sol,sag` |
| `mühərrik və sürətlər qutusunun yastıqları` | 2 опоры (эллипсис восстановлен) |

Три дефекта, найденные на живых данных и исправленные:

* **нумерация списков** — `1. Qabaq arxa apornu` больше не тащит «1.» в предмет;
* **ложное склеивание через перевод строки** — `Qabaq abirsofka` и
  `…parkradari` склеивались в несуществующий предмет `abirsofka parkradari`.
  Эллипсис теперь восстанавливается только через союз и только если сочетание
  подтверждено **контекстным правилом словаря** (`context:muherrik+yasti`).
  Просто высокого score мало: ложная пара тоже давала 0.999, но лишь потому,
  что второе слово нашлось само по себе;
* **комментарии как детали** — хвост `Hər birinin firma adı` («марку каждого»)
  помечается `is_part_request=False`. Пометка **ничего не выбрасывает**:
  предмет проходит конвейер и честно заканчивается `UNKNOWN`. Ошибиться в
  пометке дёшево, потерять реальный запрос — нет.

Контекст автомобиля (марка, кузов, год, объём двигателя) выносится в
`vehicle_context`. Слово, известное словарю запчастей, не вырезается никогда.

### OEM / part-number резолвер

Работает **до** ретривера. Отличает номер детали от VIN, года, кода кузова,
объёма двигателя, типоразмера шины, телефона и количества; собирает номера,
записанные группами (`1K0 615 301 AA`, `34 11 6 794 300`).

| статус | смысл |
|---|---|
| `MATCH` | номер и текст указывают на один объект |
| `CONFLICT` | номер указывает на **другой** объект, чем текст |
| `UNRESOLVED` | похоже на номер, но сопоставить не с чем |
| `NONE` | полезного номера нет |

**Номер никогда молча не перебивает текст.** Конфликт доезжает до валидатора и
уходит на разбор.

### Retriever V2 — код проекта, не переписанный

`vendor/retriever_v2/` — поставленная реализация, перенесённая **как есть**.
Единственные правки — разрешение путей к словарю и `danger.json`; тесты
`test_vendor_integrity.py` следят, чтобы алгоритм не «улучшали» на месте.
`avtozap/retriever.py` — тонкий адаптер: приводит вывод к типам конвейера и
добавляет метаданные из словаря 541.

Замер на реальном fresh-300 (`python scripts/measure_retriever.py`):

| что меряем | значение |
|---|---|
| shortlist содержит весь ссылочный список devset | **100.0%** |
| `old_external_code` в shortlist (поиск по `item_raw`) | **93.8%** |
| он же rank #1 | 68.9% |
| `old_external_code` в shortlist (поиск по сырому тексту) | 91.6% |
| пустой shortlist | 0 |

Первая строка — главная: при `limit=24` репозиторий воспроизводит эталонный
прогон проекта **один-в-один**, то есть адаптер ничего не исказил. Отсюда и
выбран `limit=24` (проектный замер: 16 → 89.5%, 24 → 90.7%, 32 → 91.6%).
Полнота — **не точность**: `old_external_code` не является размеченной истиной,
метрика показывает лишь, что ретривер не потерял потенциально нужный код.

**Про мои прежние правки ретривера.** В предыдущей итерации я добавлял
транслитерацию, согласный скелет и индексацию имён листьев. Поставленный V2
закрывает первые две своими средствами (alias-группы `tormuz/əyləc`,
морфологические стемы, `fuzzy_compact`) и делает это лучше. Дополнительный
проход по именам листьев я реализовал и **замерил: на fresh-300 он не изменил
ни полноту, ни ранги**, поэтому удалён — держать код, который ничего не даёт,
дороже, чем убрать. Транслитерация (`avtozap/translit.py`) осталась только там,
где её используют тесты нормализации.

### Arbiter V3 — ЗАМОРОЖЕН

`prompts/arbiter_v3.txt` — точная копия `ARBITER_V3_PROMPT.txt`, байт в байт,
под контрольной суммой `arbiter_v3.sha256`. Тест `test_prompt_is_frozen` падает
при любом расхождении, а `test_prompt_is_the_supplied_v3_verbatim` проверяет,
что это именно он (`STRICT HEAD-NOUN GUARDS`, `lupalı fara`, `difuzer`…).

Контракт ответа задан самим промптом и исполняется буквально:

```json
{"decision":"select|unknown|clarify","external_code":null,
 "confidence":"high|medium|low","reason":"max 18 words","clarification_text":null}
```

На вход подаются `original_text`, атомарный `item_raw`, `search_phrases`
сегментера, контекст автомобиля, статус и номера OEM, статус фото и кандидаты
с именами AZ/RU, категорией и синонимами. **Список кандидатов — единственный
источник допустимых кодов.** Код вне списка фиксируется как ошибка формата и
уходит в отчёт; подставлять похожий нельзя.

Температура 0, JSON-режим.

### Валидатор

| код | действие | правило |
|---|---|---|
| `V1` | REJECT | кода нет в словаре 541 |
| `V2` | REJECT | кода не было в shortlist ретривера |
| `V3` | DOWNGRADE | нет опоры в тексте — выбран родитель/сосед |
| `V4` | DOWNGRADE | конфликт OEM не разрешён |
| `V5` | REJECT | в предмете осталось несколько типов деталей |
| `V6` | REJECT | состояние конвейера противоречиво |
| `V7` | DOWNGRADE | уверенность `low` |

`REJECT` → `UNKNOWN`, `DOWNGRADE` → `REVIEW`. Точность важнее навязанной
полноты.

## Как читать `failure_analysis.md`

Каждый провал отнесён к **первому** слою, потерявшему правильный ответ:

* `Layer 0` — предмет выделен неверно;
* `OEM-резолвер` — номер обработан неверно либо не разрешён;
* `Retriever V2` — правильной детали **не было** среди кандидатов;
* `Arbiter V3` — правильный кандидат **был на руках**, но не выбран;
* `Валидатор` — арбитр был прав, а проверка его зарубила.

Пустой shortlist сам по себе провалом ретривера не считается: чаще до него
доезжает то, что деталью и не было (спецификация авто, вежливый хвост, голый
артикул). Отнести такое на ретривер значило бы отправить чинить не тот слой.

**Arbiter V3 обвиняется только тогда, когда правильный кандидат был у него на
руках.** Без размеченной истины это различить нельзя, поэтому такие строки в
отчёте появятся лишь после того, как во входе появится
`expected_external_code`.

## Флаги

| флаг | зачем |
|---|---|
| `--input ПУТЬ` | входной файл (по умолчанию `data/requests_300.jsonl`) |
| `--max-requests N` | только первые N заявок — дымовой тест |
| `--mock` | без сети: детерминированный Layer 0 и заглушка вместо арбитра |
| `--dry-run` | проверить вход, словарь, сегментацию, ретривер; API не трогать |
| `--no-resume` | начать заново |
| `--report-only` | пересобрать CSV и отчёты из готового `results.jsonl` |
| `--model` / `--segmenter-model` | модели стадий (по умолчанию `gpt-4.1-mini`) |
| `--limit N` | размер shortlist Retriever V2 (по умолчанию 24) |
| `--accept-confidence high,medium` | какие уровни уверенности считать готовым ответом |
| `--timeout` / `--max-retries` | таймаут и число попыток вызова (60 с, 5) |
| `--enable-photo` | включить слой фото |
| `--oem-catalog ПУТЬ` | каталог OEM-номеров, когда появится |

## Сверка с эталонами

Размеченных набора два, и они меряют разное — нужны оба.

| набор | заявок | что меряет |
|---|---|---|
| `data/etalon_469.jsonl` | 469 | **точность**: у каждой заявки есть правильный код |
| `data/etalon_200.jsonl` | 200 | **поведение**: 27 отказных заявок + точка отсчёта 128 |

Наборы пересекаются всего по 27 текстам, и в новом нет ни одной отказной
заявки, поэтому правило «переспроси / попроси фото» проверяется только на
наборе 200.

**Прогон эталона 469 одной командой** — вставили ключ, получили результат:

```bash
python3 PROGON_ETALON_469.py
```

Скрипт сам проверит зависимости, соберёт вход, спросит ключ (скрытым вводом,
никуда его не сохраняя), прогонит все 469 заявок и сразу напечатает результат
с разбивкой по уверенности. Прогон возобновляемый: прервали — запустите ту же
команду, продолжит с места остановки.

Пошагово, если нужно по частям:

```bash
python scripts/build_etalon_input.py                    # пересобрать оба входа
python scripts/score_etalon.py                          # потолок, API не нужен
python run_test.py --input data/etalon_469.jsonl        # прогон (нужен ключ)
python scripts/score_etalon.py --results out/results.jsonl
```

Потолок без API: **469/469 = 100%** на наборе 469 и **197/200 = 98.5%** на
наборе 200 (запас над боевыми 128 — плюс 69 заявок). На наборе 469 промахов
ретривера не осталось; три оставшихся на наборе 200 разобраны в
`ETALON_REPORT.md`. Методика подсчёта — в `METODIKA.md`.

У 27 заявок набора 200 правильный ответ — **пусто**, и это считается ответом:
выдала система код — ошибка, переспросила или отказалась — попадание.

### Правило заказчика: не угадывать

`avtozap/policy.py` переводит результат конвейера в действие:

| действие | когда |
|---|---|
| `ANSWER` | деталь определена |
| `ASK_BUYER` | не уверены — просим описать другими словами |
| `ASK_PHOTO` | покупатель сам пишет, что не знает названия |
| `PASS_TO_SHOP` | второй заход (`--attempt 2`) не помог — сырой текст магазинам |

### Дубли кодов

`data/duplicate_codes.json`: RG-04 → MU-089, MU-012 → MU-078, SO-025 → SO-005.
Дубль не попадает в shortlist, наружу отдаётся только канонический код.

## Исправления по итогам живого прогона 31.08

Подробный разбор — в `LIVE_RUN_ANALYSIS.md`. Коротко:

| что | было | стало |
|---|---|---|
| обрыв длинных ответов | общий `max_tokens=700`, обрыв выглядел как ошибка JSON | у сегментера 4000, отдельный класс `TruncatedResponse`, без бессмысленных повторов |
| порча кодировки | обнаруживалась только глазами, стоила 13 п.п. select | детектор `encoding_guard`, сводка начинается с «⛔ ПРОГОН НЕПРИГОДЕН» |
| ложные отказы «две разные детали» | арбитр судил по `original_text` | `item_raw` первым в payload + соседние предметы отдельным полем |
| две детали в одном предмете | арбитр отвечал `clarify`, заявка терялась | предмет дорезается **до** арбитра, если куски указывают на разные группы |

Дорезка намеренно осторожна: `ön bufer arxa bufer` остаётся одним предметом —
признак позиции обязан оставаться при своей детали, иначе «arxa» отрывается от
бампера и утаскивает ответ в задний фонарь.
